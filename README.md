# X Reels

A TikTok-style vertical video feed of the accounts you follow on X, installed on your iPhone like an app. Hosted entirely on GitHub: **GitHub Pages** serves the app and a scheduled **GitHub Action** fetches the videos from the official X API. No server to run, no login screen.

Live at **https://kikulwe.github.io/x-reels/**

## How it works

```
every 6 hours ──▶ GitHub Action runs scripts/build-feed.mjs
                    1. who @you follow            (X API, app-only bearer token)
                    2. recent video posts by them  (search: "(from:a OR from:b …) has:videos")
                    3. merge with the previous feed.json, keep the last 7 days
                  ──▶ deploys site/ + feed.json to GitHub Pages
your phone      ──▶ opens the page, reads feed.json, streams the MP4s from video.twimg.com
```

Two tabs: **Latest** (newest first) and **Top** (same posts ranked by likes and views). This is not X's "For You" feed — the official API doesn't offer it to third-party apps.

## Set up (once)

### 1. X developer app
1. Sign in at https://console.x.com, create a Project and an App, and add some credits (X is pay-per-use; there is no free tier).
2. Keys and tokens → copy the **Bearer Token**. Nothing else is needed: no OAuth login, no callback URL.

### 2. Repository settings
- **Settings → Secrets and variables → Actions → Secrets**: add `X_BEARER_TOKEN`.
- **…→ Variables**: add `X_USERNAME` = your X handle without the @ (e.g. `kikulwe`).
- **Settings → Pages → Build and deployment → Source**: choose **GitHub Actions**.

### 3. First run
Actions tab → **Build feed and deploy to GitHub Pages** → **Run workflow**. About a minute later the site is live with your first batch of videos. After that it refreshes itself every 6 hours.

## Install on your iPhone
1. Open the live link in **Safari**.
2. Tap **Share** → **Add to Home Screen** → **Add**.
3. Open **X Reels** from the Home Screen. Swipe up for the next video, tap to pause, tap the speaker to unmute, tap the caption to expand it, tap 𝕏 to open the post.

The app shell and the last feed are cached, so it opens offline; the videos themselves need a connection.

## Cost

X bills about **$0.005 per post read**. Each run reads only posts newer than the previous run, so cost scales with how many videos your follows actually post, not with how often the job runs. Two knobs (repository **Variables**):

| Variable | Default | What it does |
|---|---|---|
| `MAX_RESULTS_PER_QUERY` | 20 | Posts fetched per search query (10–100). Lower = cheaper, may miss videos from very active accounts. |
| `MAX_QUERIES_PER_RUN` | 20 | Search queries per run (1–100). Each query covers ~25–30 accounts; if you follow more than that covers, runs rotate through the rest. |

Worst case per run ≈ `MAX_RESULTS_PER_QUERY × MAX_QUERIES_PER_RUN × $0.005` — $2 at the defaults, usually far less because the time filter returns only new posts. The Action log prints the number of posts read and the approximate cost of each run. To run less often, change the `cron` line in `.github/workflows/pages.yml`. Set spend alerts in the X console.

## Project layout

```
site/                 the static app (what GitHub Pages serves)
  index.html          shell
  app.js              feed, snap-scroll player, offline cache
  app.css             styles
  sw.js               service worker: shell cache-first, feed.json network-first
  manifest.webmanifest, icons/
  feed.json           generated by the Action (not committed)
scripts/build-feed.mjs   fetches from the X API and writes site/feed.json
.github/workflows/pages.yml   schedule + deploy
```

### Run the builder locally
```bash
X_BEARER_TOKEN=… X_USERNAME=kikulwe node scripts/build-feed.mjs
python3 -m http.server 8000 --directory site   # then open http://localhost:8000
```

### Notes
- HLS-only posts (no MP4 variant) are skipped because Chrome and Firefox can't play them without extra code; nearly all X videos have MP4s.
- Posts are only billed once per UTC day, and the builder uses `start_time` so repeat reads are rare.
- Search covers the last 7 days only, so the feed holds at most a week of videos.
- To ship a code change, bump `CACHE` in `site/sw.js` so phones pick up the new files.
